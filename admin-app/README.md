# README.md

# TechnoTrade Academy Admin

A separate, owner-only Next.js App Router application sharing the public website’s Supabase database. Deploy it as its own Vercel project and domain. Never copy the service-role key into the public website.

## Setup

Create a Next.js TypeScript App Router project with `src/`, then replace/add the supplied files:

    npx create-next-app@latest technotrade-admin --ts --app --src-dir --eslint --use-npm
    cd technotrade-admin
    npm install @supabase/supabase-js server-only

Keep the generated root layout, TypeScript configuration, package files, and global stylesheet. Use Node.js 22 or newer.

## Environment variables

Set these in `.env.local` for local development and in the separate Vercel project's environment settings:

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL of the existing Supabase project |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-only Supabase service-role key |
| `RAZORPAY_KEY_ID` | Server-side Razorpay API key ID |
| `RAZORPAY_KEY_SECRET` | Server-only Razorpay API secret |
| `RAZORPAY_WEBHOOK_SECRET` | Server-only webhook verification secret |
| `ADMIN_EMAIL` | The one permitted owner's email |
| `ADMIN_PASSWORD_HASH` | Owner password hash described below |

Do not prefix secrets with `NEXT_PUBLIC_`, commit `.env.local`, or pass secrets to client components. Razorpay credentials are reserved for future payment operations; these files do not create payments or expose a webhook endpoint.

Generate the password hash locally using Node's scrypt. This command prompts without placing the password in command history:

    read -s -p "Owner password: " ADMIN_PASSWORD; echo
    export ADMIN_PASSWORD
    node -e 'const c=require("node:crypto"); const s=c.randomBytes(16).toString("hex"); console.log("scrypt$"+s+"$"+c.scryptSync(process.env.ADMIN_PASSWORD,s,64).toString("hex"))'
    unset ADMIN_PASSWORD

Copy the entire output into `ADMIN_PASSWORD_HASH`. In `.env.local`, escape each `$` as `\$` because Next.js expands dollar references. In Vercel's environment editor, paste the raw output without escaping.

## Database contract

No migration or schema change is performed automatically. Verify that the existing tables expose these columns; adapt the queries if your schema differs:

- `users`: `id`, `role` (`student` for students)
- `courses`: `id`, `title`, `slug` (unique), `description`, `price`, `status` (`draft` / `published`)
- `course_modules`: `id`, `course_id`, `title`, `display_order`
- `course_lessons`: `id`, `module_id`, `title`, `video_url`, `video_type`, `is_free_preview`, `display_order`
- `orders`: `id`, `status` (`pending` for pending orders)
- `payments`: `id`, `amount`, `status` (`captured` for successful payments)
- `enquiries`: `id`
- `ads`: `id`, `title`, `image_url`, `html_code`, `link_url`, `placement`, `start_at`, `end_at`, `is_active`, `display_order`

IDs must be generated by the database. Monetary values are integer INR paise. Revenue is gross captured payment revenue, not net of refunds. Date columns use `timestamptz`; blank optional ad fields become `NULL`.

Enforce foreign keys from modules to courses and lessons to modules with `ON DELETE CASCADE`. Course deletion may still be blocked by enrollment/order references; archive such courses as drafts instead. Enforce valid statuses, nonnegative prices, and unique course slugs in the database.

Keep RLS enabled for public clients. The service-role client bypasses RLS, so every supplied page and mutation checks the owner session. Never import the admin client into public/client-side code.

## Security and ads

- There is no registration or student login. Only the configured owner can sign in.
- Sessions use signed, HTTP-only, SameSite cookies, expire after eight hours, and are signed using a server-side key derived from the service-role key and owner credentials.
- Changing the owner credentials or service-role key invalidates existing sessions.
- Mutations use Next.js Server Actions with built-in same-origin checks. Do not broaden Server Action allowed origins.
- Before exposing the app publicly, configure a Vercel Firewall rate-limit rule for POST requests to `/`, or put the deployment behind an equivalent access gateway. In-process rate limiting is not reliable across serverless instances.
- New ads are inactive by default, and this admin app never renders ad images or HTML.
- The separate public app must explicitly implement ads, query only active ads within their schedule, and keep ads disabled until intentionally enabled. These files do not alter existing public-site behavior or existing ad records.
- Treat ad HTML as untrusted. Never render it directly in the public page DOM; use a tightly sandboxed iframe and an appropriate CSP.

## Local development

    npm run dev

Visit `http://localhost:3000` and sign in with the configured owner credentials.

## Separate Vercel deployment

1. Push this admin project to its own repository, or use a separate directory in a monorepo.
2. Import it as a **new Vercel project**. For a monorepo, set its Root Directory to the admin directory.
3. Select the Next.js framework preset and Node.js 22 or newer.
4. Add the environment variables above to Production. Configure Preview separately; avoid giving untrusted preview deployments production database access.
5. Deploy and attach a dedicated domain such as `admin.example.com`.
6. Configure the firewall/access gateway, test owner login, and confirm unauthenticated requests cannot access `/courses` or `/ads`.

Dashboard, courses/modules/lessons, and ads are implemented here. Promo, Orders, Payments, Enquiries, and Community links reserve routes for additional authenticated pages; those pages are not part of these five files. The Lessons link opens the course lesson manager.
