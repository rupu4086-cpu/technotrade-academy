# TechnoTrade Academy

Online trading course website — Stock, Crypto and Forex courses, with paid checkout
via Razorpay, promo codes, student learning pages and a separate hidden admin area.

Code generated by GPT-6 Astra (model `gpt-6-astra`) from the owner's brief, extracted
verbatim from the Astra output files into this repository. No secrets are hardcoded
anywhere in this repo — all keys are supplied through environment variables.

## Stack

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- Prisma + PostgreSQL (Supabase is the recommended host)
- Razorpay Checkout — server-side order creation, signature verification, and
  access granted only after a verified **captured** payment. A paid course is
  never unlocked before payment is verified.
- Promo codes calculated server-side only (see `src/lib/pricing.ts`)

## Environment variables

Copy `.env.example` to `.env.local` (local only — never commit it) and fill in your
own values. In Vercel, set the same variables under Project Settings → Environment
Variables. The Supabase service-role key is **server-only** — never put it in the
public website's client-side variables.

| Variable | Where it is used |
| --- | --- |
| `DATABASE_URL` | Prisma — PostgreSQL connection string (Supabase) |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon (publishable) key |
| `SUPABASE_SERVICE_ROLE_KEY` | Admin app server only — never in the browser / public site |
| `RAZORPAY_KEY_ID` | Razorpay key ID (server) |
| `RAZORPAY_KEY_SECRET` | Razorpay key secret (server only) |
| `RAZORPAY_WEBHOOK_SECRET` | Razorpay webhook secret (server only) |
| `NEXT_PUBLIC_RAZORPAY_KEY_ID` | Razorpay key ID exposed to the checkout page |
| `ADMIN_EMAIL` | Admin app owner login email |
| `ADMIN_PASSWORD_HASH` | Admin app owner password hash (never a plain password) |
| `ADMIN_PRIVATE_PATH` | Secret path segment for the hidden admin route |
| `SESSION_SECRET` | Session signing secret |
| `SETTINGS_ENCRYPTION_KEY` | Encryption key for stored settings |
| `APP_URL` | Public site URL, e.g. `https://technotrade-academy.vercel.app` |
| `NEXT_PUBLIC_SUPPORT_EMAIL` | Support email shown on the site |

## Local development

```bash
npm install
cp .env.example .env.local   # fill in your own values
npx prisma migrate deploy    # or: npx prisma migrate dev
npm run dev
```

## Deploy (Vercel)

1. Import this repository as a new Vercel project (Next.js preset, Node 22+).
2. Add the environment variables above to Production.
3. Deploy. The admin app in `admin-app/` must be imported as a **separate**
   Vercel project with its Root Directory set to `admin-app/`, using the same
   Supabase URL and the service-role key only in that project's server env vars.

## Rules baked into this code

- No certificates (the academy is not a company issuing certificates).
- No ads by default; ads are managed only from the admin app and are off by default.
- No profit guarantees and no fabricated testimonials.
- Checkout rule: pending order first, **never** unlock a course or mark an order
  paid before a verified Razorpay payment; signature + webhook verification,
  idempotent webhooks. If Razorpay keys are not configured, checkout shows
  "Payment setup pending" and does not unlock anything.

## Known gaps (from the Astra output — not yet fixed)

The Astra files did not include the usual Next.js scaffold, so this repo will
**not build as-is** until these are added:

- `src/app/layout.tsx`, `src/app/globals.css`, `tailwind.config.*`,
  `postcss.config.*`, `tsconfig.json`, `next.config.*` — none were supplied.
- `pg` (used by `src/app/api/checkout/route.ts`) and `@supabase/supabase-js`
  (used by `admin-app/src/lib/supabase-admin.ts`) are imported but are **not**
  listed in `package.json` dependencies.
- The public pages use a local SQLite-backed store in places
  (`node:sqlite` in the course-detail / learn / admin pages), while the Prisma
  schema targets PostgreSQL — the two stores need reconciling before launch.
- The admin app's Promo, Orders, Payments, Enquiries and Community pages are
  linked but not implemented (its own README says so); only Dashboard,
  Courses/Modules/Lessons and Ads are in `admin-app/`.
- The Supabase SQL schema for the tables lives in the owner's Supabase project
  (15 tables already created there); Row Level Security is **off** and policies
  still need to be added before a Supabase-backed deployment goes live.
